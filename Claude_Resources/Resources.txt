Differences from the main spec (decided 2026-11-10):
- NEW: board changes appear live for every open page (WebSocket), not only after a reload.
  The server only announces "table N changed" (plus a version number); each page fetches the updated row over HTTP
  with its own login, so pushes never carry user-specific or admin-only data. After a reconnect the page catches up
  by comparing the version (whole board refetched if anything was missed). Own actions update the row without a
  full reload; without JS, forms still work as normal posts.
- OUT of v1: passkeys, two-factor authentication, external logins (and their pages). 2FA comes later: the login
  is a step-by-step flow and sessions carry an auth level, so a second step can be inserted.
- Accounts and passwords are kept: old ASP.NET Identity v3 hashes are verified, and re-hashed (scrypt) on the next
  successful login. Users are logged out once at cutover (new cookies).
- Existing 2FA/passkey settings and external logins are not migrated; the migration script lists any account that
  had 2FA switched on.
- Roles are stored as one value per user (owner / admin / user) instead of Identity's role tables; the rules are
  unchanged (Owner is always also Admin, only the Owner manages admins, nobody changes the Owner).
- Ported too (unchanged rules from the main spec): dev-only tools (page designer with the same JSON format, 4 test
  users), the temporary Google sheet import (kept isolated in src/import/), the feedback box file format.

Stack (decided 2026-11-10, phase 0 approved with all recommendations):
- Node.js current LTS; TypeScript run directly by Node (type stripping), tsc only type-checks.
- Fastify; HTML from our own escaping `html` tagged templates; Bootstrap 5; plain browser JS with // @ts-check.
- SQLite (stay on Mikrus 2.1): better-sqlite3 + Kysely; hand-written, numbered migrations.
- Hand-written database sessions (only the id's hash stored; HttpOnly, SameSite=Lax, Secure cookies);
  CSRF token + same-origin check on every non-GET request; Origin check on the WebSocket upgrade.
- WebSocket via @fastify/websocket with a hand-written reconnect (growing delays, max 30 s).
- Tests: node:test + Fastify inject() + in-memory SQLite; a few Playwright browser tests from phase 3.
- Background jobs (weekly reset, sheet import): in-process timers; Europe/Warsaw time computed explicitly.
- Config: .env locally (git-ignored, .env.example committed), environment variables on the server; validated at startup.
- npm packages approved for adding when their phase needs them: fastify, @fastify/cookie, @fastify/formbody,
  @fastify/static, @fastify/multipart, @fastify/websocket, kysely, better-sqlite3, nodemailer, fast-xml-parser;
  dev: typescript, @types/node, @types/better-sqlite3, @playwright/test. Others: ask first.

Data (decided 2026-11-10):
- New clean schema (snake_case) plus a one-time, tested migration script (scripts/import-dotnet-db.ts) from the
  .NET app.db, run on a local copy in phase 4 and at cutover in phase 5.
- Existing ids are kept (user ids, table and game ids), so action-log entries and feedback files still match.
- Covers stay as BLOBs in the database. The BGG weight is kept as text, shown exactly as BGG gives it.
